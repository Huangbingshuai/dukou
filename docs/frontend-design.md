# 前端设计：渡口

## 一句话

页面只回答一个问题：**这段对话，哪些工具已经有了？** 答案是一行三个标签。

## 之前为什么乱

上一版把内部实现摊在了界面上：254 行（同一段对话在不同工具里各占一行）、7 个按钮、三个「骑缝孔」需要先读懂含义，还要先勾选再选目标再点执行。用户的任务只有一句话——「把这段对话也放到那个工具里」——界面却要求他先建立一套心智模型。

## 现在的结构（照 Codex 客户端）

```
┌ Codex ⌄            ⟳ │  对话标题                    ◎ ✳ 发送到 … │
│ ┌ 搜索对话 ────────┐ │  Codex · ~/code/ai-marketing · 6 小时前   │
│ ▸ 项目               │ ─────────────────────────────────────── │
│ ▸ ai-marketing 89    │  这是一段助手正文……                      │
│ ▸ Star Proxy   19    │                                         │
│ ▾ code          3    │  调用 exec text(await tools.apply_patch…  │
│    AI 对话记录…       │  结果 [{"type":"input_text",…            │
│    拉取这个项目…      │                                         │
│ ▸ 最近               │  ▸ 用户气泡（右对齐）                     │
└──────────────────────┴─────────────────────────────────────────┘
```

左侧 288px 固定，右侧正文限宽 720px 居中；正文头部吸顶。工具切换、项目树、最近列表都在侧栏里，右侧只做阅读与「发送到另一个工具」。

工具调用沿用 Codex 的做法：默认压成一行（标签 + 省略的命令），点一下展开完整内容，再点收起。

排序稳定性是硬约束：列表只按对话自身的时间排（分组会话取副本文件 mtime），镜像轮次不参与，因此后台跑多少次同步都不会让条目跳动。

## 视觉语言（高级感来自克制）

- **纸张**：`#f7f5f0` 暖白纸面，加一层几乎看不见的双径向渐变（左上提亮、右上极淡的赭红），不用图片、不用噪点。
- **墨**：正文 `#1a1a1a`，次级 `#4a4844`，弱 `#8b8780`；分隔线是 9% 与 16% 的墨，不是灰色。
- **唯一的强调色**：赭红 `#7a3b2e`。只出现在四个地方——品牌标记、已齐全那个数字、搜索命中、错误提示。其余全部黑白。
- **字体分工**：品牌与对话标题用宋体（`Songti SC`），数字用宋体大字距版式，标签/时间/日志用等宽，正文用系统无衬线。中文界面里衬线标题本身就是一种讲究。
- **数字**：统计栏五个数用衬线体、等宽数字，配 9.5px 拉宽字距的等宽小标签，中间用发丝线分隔。
- **工具标签**：不再用三种颜色。实心墨色 = 已有，虚线发丝 = 缺失。颜色退场后，形状与明暗承担语义，界面立刻安静下来。
- **动效**：首屏 12 行做 14ms 递增的 5px 上浮；标签 hover 上移 1px；焦点环 1.5px 赭红。`prefers-reduced-motion` 下全部关闭。
- **没有**：卡片阴影、圆角卡片、图标库、渐变按钮、悬浮工具条。层级只靠留白、发丝线与字号。

## 交互细节

- 点虚线标签 → 标签进入 `…` 忙碌态 → 完成后变实心，底部浮出一条结果（「已复制 110 条内容到 Codex。」）。
- 点标题 → 浮出这段对话的概况（消息数、项目、最近一次出现在哪个工具）；空会话会被明确指出来。
- 搜索实时过滤并高亮命中片段；`/` 聚焦搜索框。
- 实时：后端监听三个存储，收敛后通过 SSE 通知页面自动刷新，日志里留一行。
- 键盘可达，焦点环可见；`prefers-reduced-motion` 下无动画。

## 名字

**渡口**（Dukou）——对话从这里渡到另一个工具去。备选：驿站、同文。
